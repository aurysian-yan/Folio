# 侧栏分页切换甩尾动画方案

> 状态：macOS SwiftUI 端曾尝试实现并最终移除，当前为无动画即时切换。本文保留目标效果、已踩过的坑和参数建议，供 Windows/Linux 的 Tauri/React 前端实现时参考。规划内容不代表已实现。

## 1. 背景

侧栏有两个分页：**导航**与**筛选**，通过工具栏分段控件切换。切页时需要一种「甩尾」动效，而不是生硬的整块切换。

相关提交：

- `471e2fb` 引入位移转场与逐行延时（macOS）。
- 后续提交将其整体移除（受 `List` 行复用限制，见第 3 节）。

## 2. 目标效果

- **容器静止**：侧栏是同一个固定滚动区域，切页时滚动容器本身不位移、不淡入淡出；只有内容元素在动。
- **元素甩尾**：当前页的每一行、每个区段标题、每张筛选卡片，按顺序做「水平位移 + 透明度」过渡，序号越大延时越长，形成逐条跟上的甩尾感。
- **方向固定**：
  - 导航页在左、筛选页在右；
  - 切到筛选时，元素整体向左流动（导航向左退出，筛选从右侧进入）；
  - 切回导航时，元素整体向右流动（筛选向右退出，导航从左侧返回）。
- **首次不播放**：窗口刚创建、首次渲染时不做任何位移或淡入。
- **可重复**：每次切换都完整重放，连续切换多次强度不衰减。
- **滚轮不切页**：鼠标滚轮只用于滚动列表，不用于切换分页；分页由点击分段控件或键盘切换。
- **无障碍**：遵循 `prefers-reduced-motion`，开启时直接显示、不做位移。

## 3. macOS 端为何放弃

macOS 用 SwiftUI `List` 承载侧栏，逐行自定义转场难以做可靠，实测问题包括：

1. **可选中行会被重载**：`List(selection:)` + `.tag(...)` 的行在切页、选中态变化时被 `List` 重载，行内动画状态被重置，结果只有无 `tag` 的行（如「新建收藏夹」按钮）会动。
2. **行内状态会耗尽**：用行内 `@State` + `onAppear`/`onChange` 触发动画时，`List` 的行复用/懒加载导致状态不再复位，切换三到四次后动画完全消失。
3. **容器整体平移**：用页面级 `.transition` + `.move` 会变成整个滚动容器平移；配 `.id` 换页时，插入与移除可能读到不一致的方向状态，导致方向翻转（如筛选页错误地向左退出）。
4. **多滚动容器**：为交叉淡入保留两页并存时，会出现两个滚动区域、双份背景，观感上仍是「两个容器在动」。

结论：SwiftUI `List` 不适合逐行自定义转场，因此 macOS 端移除动画，改为无动画即时切换（`SidebarView.sidebarPageContent` 只渲染当前页）。

## 4. React/Tauri 实现建议

React 直接控制 DOM，没有 `List` 行复用问题，可以用纯 CSS 过渡稳定实现。

### 4.1 结构

- 使用**一个**滚动容器（如侧栏列内的 `overflow-y: auto`），内部只渲染当前分页内容；不要在滚动容器上做 `transform`/`opacity` 动画。
- 用一个状态表示当前页（`'navigation' | 'filters'`），据此渲染对应内容。
- 每个需要动画的元素（行、区段标题、筛选卡片）带上序号，例如内联样式 `style={{ '--stagger-index': i }}` 或 `data-stagger-index={i}`。
- 元素顺序（建议）：区段标题与其首行使用相近序号，标题略靠前，避免标题和首行一起「卡住」。

### 4.2 动画方式

每个元素保持如下默认与进入两态，用类名或 `data` 属性切换：

```css
.sidebar-item {
  --entry: 0px;                 /* 导航为负、筛选为正 */
  opacity: 0;
  transform: translateX(var(--entry));
  transition:
    transform var(--motion-duration) var(--motion-ease),
    opacity var(--motion-duration) var(--motion-ease);
  transition-delay: min(
    calc(var(--stagger-index, 0) * var(--stagger-step)),
    var(--stagger-cap)
  );
}

.sidebar-item[data-entered="true"] {
  opacity: 1;
  transform: translateX(0);
  /* 已进入后清掉延时，避免后续状态变化被延时影响 */
  transition-delay: 0ms;
}
```

- **重放**：每次切页给分页内容一个变化的 `key`（如 `key={page}`）让它重新挂载，或用一个递增的 `transitionToken`，切页后在下一帧把 `data-entered` 置为 `true`，确保每行都从位移态过渡到归位。
- **首次不播放**：维护 `hasMounted`（或首帧标记），首次渲染直接以「已进入」状态渲染，不经过过渡。
- **方向**：导航页元素 `--entry: -56px`，筛选页元素 `--entry: 56px`；两个方向都在 CSS 里定型，不要用会在不同时机读到的可变「步进」值。

### 4.3 参数起点

| 参数 | 建议值 |
| --- | --- |
| 位移振幅 | 44–56px（或侧栏宽度的 18%–24%） |
| 时长 | 500ms |
| 缓动 | smooth 曲线，如 `cubic-bezier(0.22, 1, 0.36, 1)` |
| 逐行延时步长 | 25ms |
| 延时上限 | 300ms |

数值集中为设计 token，便于统一调整。

### 4.4 必须一起动画的元素

不要只给「普通行」加动效，否则会出现标题不动、卡片不动的问题：

- 区段标题：本地、收藏夹、云端、字体状态、工具、筛选；
- 普通导航行、云端行、新建收藏夹、在线字体、筛选卡片等所有行类型。

## 5. 验收清单

- [ ] 切页时滚动容器不移动，只有元素逐条甩入/甩出；
- [ ] 窗口首次创建时无任何位移或淡入；
- [ ] 连续切换 10 次以上动效强度不衰减；
- [ ] 导航固定从左侧、筛选固定从右侧，方向不翻转；
- [ ] 鼠标滚轮不切换分页；
- [ ] 开启 `prefers-reduced-motion` 后无位移；
- [ ] 始终只有一个滚动区域/滚动条。

## 6. 与其它平台的关系

- macOS 端保持当前无动画实现；若未来要重做，需先解决第 3 节的 `List` 限制，或改用非 `List` 的自定义行容器。
- Windows/Linux 由同一套 React 页面承载，本文方案只需实现一次；数据与交互语义仍由共享 Rust 能力提供，动画不改变查询或选中语义。
