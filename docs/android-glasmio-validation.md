## 根因证据

原始取样使用不透明洋红色测试底板，以区分真实页面底色和透明漏出。
测试同时读取未经材质处理的取样像素和完整 `GlassSurface` 输出。
第二轮基线已经使用新上游、仍保留旧 Folio 桥接实现，因此升级本身没有修复这些问题。

| 场景 | 旧桥接原始取样 | 修复后原始取样 |
| --- | --- | --- |
| 已录制的绿色内容 | `ff00ff00` | `ff00ff00` |
| 消费者移出源边界 | `ffff00ff`（底板漏出） | `fff0f0f5`（页面底色） |
| 背景源释放 | `ffff00ff` | `fff0f0f5` |
| 坐标暂不可用 | `ffff00ff` | `fff0f0f5` |
| 页面恢复 | `ff00ff00` | `ff00ff00` |

确认的问题：

1. `OnlineFontsScreen` 原采样容器被 `browserBottom` 缩短，地址栏和底栏位于源边界之外。
   消费者直接绘制 RenderNode 时，越界部分没有不透明像素；只给节点内部填色无法覆盖它。
2. `active=false` 会注销并释放源；旧消费者在无节点、未录制或无坐标时直接返回，
   完全缺源时使用空 Backdrop。仍可见的玻璃因此将透明输入交给材质和内阴影混合。
3. 原生消费者移动后，不一定触发 Compose 重新取样。基线中原始取样已越界，
   完整玻璃仍保留绿色旧帧；源释放后才改为漏出洋红底板。
4. 后台测试发现窗口隐藏后的最后一帧可以重新创建刚释放的节点。
   绘制入口增加窗口与视图可见性检查后，后台确实无录制，恢复后重新得到绿色实时内容。

修复在取样画布最底层绘制所属页面当前 `theme.background`，再叠加实时源，
两者共同经过现有模糊、折射、内阴影与材质。源内部也填入同一底色。
消费者保有独立的页面色，缺源时不借用其他页面，也不永久保留图层。

完整材质对照中，正常采到不透明空白页面、越界保底、释放保底及缺源保底的中心像素
均为 `fff9f9fc`，材质输出一致。未删除或减弱任何内阴影。
由此区分了透明取样导致的异常输出与正常轮廓阴影；原始像素问题不依赖网页加载结果。
页面坐标变换已包含 Compose 图层变换，测试中缩放、位移后由绿色区域正确采到蓝色区域，
没有额外叠加一次 `layerBlock` 的逆变换。

## 胶囊轮廓补充

按用户后续截图要求，在线地址栏的 `navigationGlass` 使用 `Capsule()`，
独立搜索按钮也显式使用相同轮廓；导航轨道与选中拨片保留上游已有的 `Capsule()`。
各轮廓按当前布局尺寸计算，不使用地址栏面板的固定 24 dp 圆角。
此补充保留共享材质、按压、拖动与回弹，未改动其他面板形状。
补充修改后的 arm64-v8a、x86_64 Release APK 均重新构建通过。
按用户要求，不再进行模拟器测试；前述视觉与 36 项设备验证对应背景修复阶段。

## 限制与交付

- Android 完整 Lint 在依赖 `:react-native-worklets:lintAnalyzeDebug` 中崩溃，错误为
  `findFirCompiledSymbol only works on compiled declarations`（Kotlin FIR／Lint 内部错误）。
  单独请求 Folio 的分析任务仍会先触发同一个依赖任务；未修改依赖或添加抑制规则。
  TypeScript／ESLint、原生编译、单元测试及 APK 构建结果独立通过。
- x86_64 只完成编译与 APK／JNI 产物核对，未运行该架构的模拟器。
- 跨窗口映射完成源码核对，尚未做独立窗口像素对照。
- 未覆盖全部 Android 厂商 WebView、所有屏幕尺寸、长时间性能和所有菜单拖动手势。
  JNI 的三个宿主单元检查未执行，不将编译通过等同于其数值断言通过。
- 模拟器安装使用开发身份 `com.folio.mobile.poc.dev` 的 Release 包，保留现有数据与连接配置。
  App 包含完整 JS，运行无需开发服务；模拟器与 App 按用户要求保留运行。
