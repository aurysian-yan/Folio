# Tauri 字体加载性能优化记录

## 实现与行为

选中字体立即更新高亮和检查器，访问记录顺序写入后台，不重新取回首屏，也不丢失已加载页。最近查看及最近排序保持当前位置，重新进入或手动刷新时更新顺序。最近数量即时更新，智慧收藏夹统计在后台合并刷新。保存访问记录只重新读取最近列表，复用收藏、来源和目录状态，避免反序列化整份字体缓存。

字体命令使用二进制响应：4 字节小端元数据长度、UTF-8 JSON（`coverage`、`sample`）、完整 sfnt 字节。前端共享响应缓冲区创建 `FontFace`。普通独立字体复用原文件；TTC 提取指定字面，带 DSIG 的字体重建并移除失效签名。原生图片预览仍用于浏览器拒绝的字体。

读取、导出、查询、最近记录和原生栅格化在阻塞线程池执行。字面来源使用桌面层索引；字体库锁内只取来源快照，文件读取和栅格化在锁外执行。Rust 缓存按文件大小、修改时间、字面索引和目录代次区分来源，并共享并发导出。

队列优先处理选中／检查器、可见、邻近字体；后台并发 2，交互保留槽 1。每个滚动区域共享可见区和预加载区两个观察器，卡片进入可见区及时提升优先级，不同步读取卡片布局。无使用者的排队任务取消，在途任务完成后若已过期，不注册字体或更新界面。浏览器拒绝的字面在本次目录代次内直接使用原生预览，避免反复传输同一大字体。

Rust 字体缓存预算为 128 MiB，图片缓存为 32 MiB。前端字体缓存同时限制 64 项和 128 MiB 原始字体字节估算量；可见字体保留，释放后回收超额闲置项。预算不代表 WebView 解码后的实际内存占用。目录刷新清空两端缓存；来源文件大小或修改时间变化使 Rust 旧缓存失效。

四种视图按行虚拟化，上下各预留 2 行，另保留焦点所在行。保留原有卡片比例与间距；接近已加载列表底部时，提前两屏或至少三行自动预取下一页，视口未填满时继续补页。移除底部分页区域，不显示已加载／总数字样或“加载更多”按钮，后台追加保留滚动位置、选中项和焦点。分页防重复触发并忽略过期响应；返回页没有新增字族时停止自动补页，刷新首屏后可重新触发。Tab、方向键、Home、End 支持跨虚拟行聚焦，视图或宽度改变时保留滚动锚点和焦点。字族位置索引随分页更新，滚动时不扫描全部已加载字族。

Hero、排序区、空状态和字体卡片共用滚动区域，底部预览栏固定。虚拟列表计入 Hero 的实时高度，并观察头部与视口尺寸变化，使自动预取、键盘定位和滚动锚点保持正确；仍在浏览 Hero 时，切换视图不跳过头部。

按用户后续选择，预览严格使用设置字号：48px 即为 CSS `font-size: 48px`。移除自动适配和字体尺寸测量，字体加载完成后直接按目标字号显示；长文本换行，超过卡片行数或预览区域时截断。卡片和侧边栏共用此行为，原生回退图片保持像素比例，不缩放到容器。预览字号保存到 `folio-preview-size`，设置窗口和主窗口通过现有偏好同步机制双向更新，重新打开窗口仍保留该值。

## Windows 本机后台采样

采样时间：2026-09-29。每个字体各执行 10 次；P95 为排序后第 95 百分位。基线在测试内复现旧实现的读取、重建、字符覆盖生成、Base64 编码和 JSON 响应序列化。新实现包含读取、导出、二进制封包、来源检查及返回缓冲区复制。

“冷”表示清空应用内导出缓存，未清空操作系统文件缓存。“热”表示命中导出缓存。这些结果不包含 WebView IPC 消费、`FontFace` 解析和页面绘制，不能据此认定完整 UI 的 100 ms 目标已通过。

| 字体 | Debug 旧实现 P95 | Debug 最终冷 P95 | Release 旧实现 P95 | Release 二进制冷 P95 | Release 热缓存 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Arial | 59.58 ms | 1.43 ms | 6.27 ms | 1.18 ms | 0.27 ms |
| Noto Sans SC 可变字体 | 1022.55 ms | 13.84 ms | 51.70 ms | 11.78 ms | 3.14 ms |
| Noto Serif SC 可变字体 | 1443.22 ms | 17.25 ms | 83.94 ms | 16.40 ms | 4.07 ms |
| 明体 TTC 第一个字面 | 1982.09 ms | 47.00 ms | 110.08 ms | 38.99 ms | 5.75 ms |

明体响应从 49,373,548 字节降至 37,030,258 字节，约减少 25%。Debug 旧实现数据使用原始依赖编译设置；最终实现仅将 `read-fonts` 开发编译优化级别设为 2，应用代码仍可调试，Release 编译设置保持原样。

初次二进制实现的明体 Debug 冷加载 P95 为 451.64 ms。独立分段采样确认重建是主要热点：整表校验和计算位于 `read-fonts`，优化该依赖后重建 P95 从 454.60 ms 降至 18.99 ms，最终冷加载 P95 为 47.00 ms。这是分别采样的 P95，不应直接相加。

| 明体 TTC 导出阶段 | 原始 Debug P95 | 优化依赖后 Debug P95 |
| --- | ---: | ---: |
| 文件读取 | 29.36 ms | 13.13 ms |
| 字符覆盖遍历 | 1.76 ms | 1.35 ms |
| 字体重建 | 454.60 ms | 18.99 ms |
| 二进制封包 | 12.70 ms | 9.87 ms |
| 返回缓冲区复制 | 10.42 ms | 6.39 ms |

最近记录在本机数据库的只读备份上采样，测试另建临时副本写入，不修改用户数据库。字面总数 383，每种实现各 20 次：Debug P95 从 58.13 ms 降至 12.13 ms，Release 从 20.93 ms 降至 12.03 ms。该指标包含数据库提交及查询索引状态更新，排除了 IPC 和界面绘制。

复现命令（从仓库根目录运行）：

```powershell
cargo test --locked --manifest-path apps/desktop-ui/src-tauri/Cargo.toml --lib preview_performance -- --ignored --nocapture
cargo test --release --locked --manifest-path apps/desktop-ui/src-tauri/Cargo.toml --lib preview_performance -- --ignored --nocapture
cargo test --locked --manifest-path apps/desktop-ui/src-tauri/Cargo.toml --lib preview_export_stages -- --ignored --nocapture
```

最近记录采样需将 `FOLIO_PERFORMANCE_DATABASE` 指向独立、一致的数据库快照，再执行同一测试命令并将筛选名换为 `recent_performance`。测试内部再次复制快照后才写入；不直接使用正在运行的数据库文件。

## WebView 采样与验收

开发构建自动安装本机内存指标；发布构建采样需设置 `VITE_FOLIO_PERFORMANCE=1` 后重新构建。没有遥测上传或界面调试文字。WebView 开发者工具控制台提供：

```javascript
window.folioPerformance.reset();
// 完成连续选中、滚动、返回已浏览字体等操作后读取结果。
window.folioPerformance.snapshot();
```

结果包括选中反馈、可见预览出现、字体 IPC、元数据解码、浏览器字体加载、列表查询、主线程长任务，以及字体缓存占用、挂载卡片数和注册字体数。每类最多保留最近 1000 条样本。选中反馈与预览出现使用后续绘制帧计时。

在同一字体库、窗口尺寸和视图下分别记录 Debug、Release 的冷／热缓存操作，验收选中反馈和热缓存预览 P95 ≤100 ms、普通选中不增加列表查询、冷加载 P95 与滚动长任务低于旧版本基线，以及挂载数量和闲置缓存有界。浏览器指标尚未进行真实 WebView 帧采样，本机 WebView 未开放远程调试接口。

## 自动验证

49 项前端测试覆盖二进制契约、共享请求、交互优先槽、可见区优先级切换、离屏取消、过期结果、字节回收、连续浏览 512 个字面的缓存预算、字体样式切换、严格字号、独立设置窗口与主窗口的字号保存和同步、原生回退、分页竞态、自动预取与补页、后续页选中、Hero 共用滚动区域及高度变化后的定位与焦点，以及 OverlayScrollbars 的视口保留、弹层接管、实例清理和左侧状态卡动态避让。

15 项常规 Rust 测试覆盖二进制契约、独立字体复用、DSIG 去除、TTC 字面、CFF 和可变轴保真、缓存预算、并发导出共享、来源变化、目录失效，以及最近记录更新后的收藏、来源和查询一致性。另有 3 项需主动执行的本机性能采样测试。

本机仅安装 Windows Rust 目标，没有可用的 Linux／WSL 环境；Linux 编译与桌面运行验收仍需在 Linux 环境执行。新增逻辑未引入平台 API，仍使用共享 React 和桌面层 Rust 实现。
